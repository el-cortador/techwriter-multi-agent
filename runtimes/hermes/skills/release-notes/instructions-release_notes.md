Сгенерируй только release notes на русском языке строго по шаблону ниже. Не добавляй changelog и разделы Added / Changed / Fixed / Removed. Не придумывай факты.

## Правила

- Используй только данные из переданных задач или коммитов. Не перечисляй задачи списком «ключ — название»: описывай изменения для пользователя связным текстом.
- Не указывай ключи Jira, SHA коммитов и имена авторов в тексте release notes.
- Сохраняй порядок и названия разделов шаблона. Не добавляй свои разделы, вступление и выводы вне шаблона.
- Если данных для раздела или поля нет, не выдумывай их — вставь плейсхолдер `[Уточнить: <что нужно>]`.
- Пиши нейтральным техническим стилем, в прошедшем времени для фактов («Добавлено», «Реализована», «Переработан») и в настоящем времени для описания поведения системы.
- Названия элементов интерфейса, опций и полей выделяй жирным; пути, переменные, параметры, эндпоинты и имена файлов — моноширинным шрифтом.
- Убери служебные изменения: merge, bump version, chore, обновления зависимостей, рефакторинг без пользовательского эффекта.

## Распределение по разделам

- Эпик, Story, New Feature и другие задачи с новой пользовательской возможностью → отдельный подраздел `###` в разделе «Что нового». Каждый эпик — отдельная возможность.
- Дочерние задачи эпика (блок «Дочерние задачи эпика») — источник подробностей для подраздела этого эпика: по ним пиши описание и абзац «Что изменилось для пользователя:». Отдельными подразделами или пунктами их не выноси. Исключение — изменения эндпоинтов из дочерних задач: их также перенеси в раздел «Изменения в REST API».
- Improvement, Task и исправления ошибок (Bug) → пункты раздела «Улучшения». Исправления формулируй как «Исправлена ошибка, из-за которой …».
- Новые, измененные и удаленные эндпоинты, упомянутые в задачах → раздел «Изменения в REST API».

## Требования к разделам

- Пункты «Сводки» совпадают по формулировке и порядку с заголовками `###` в разделе «Что нового».
- Каждый подраздел `###` в «Что нового» обязательно содержит абзац описания и абзац **Что изменилось для пользователя:**. Если описания задачи недостаточно для абзаца «Что изменилось для пользователя:», сформулируй его осторожно по названию задачи и добавь `[Уточнить: подробности для пользователя]`.
- Если в данных нет улучшений, в разделе «Улучшения» вставь `[Уточнить: улучшения не найдены в переданных задачах]`.
- Если в данных нет изменений REST API, оставь заголовок «Изменения в REST API» без подразделов и вставь `[Уточнить: изменения REST API не найдены в переданных задачах]`. Если есть изменения только одного вида, выведи только соответствующие подразделы.
